# Findings

Home DeviceStatusScreen has zoomable and nonzoom trajectory overlays, 500-sample actual trace stored in DeviceStatusUiState. Rendering uses grinding-disc center (from footprint/length), per-pass color and per-point circles. Robot icon position comes from last projected trace sample. Task change/IDLE clears trace, pause retains. Existing map projection rejects off-map points; mapNotNull currently may connect across invalid positions. Planned FittedTaskPathOverlay is already batched/cached and not capped by this500limit.

Chosen design: compact world-disc-center polyline, drawn as cached round-cap/round-join Path stroke of existing0.9m disc width (continuous swept band, no per-sample circles). Keep newest robot pose separately, no raw-pose500list. Stream simplify with absolute perpendicular tolerance0.01m, not repeated arbitrary point dropping: anchor angular corridor intersection for all merged points and nondecreasing anchor radius ensure every merged sample is within tolerance of current segment; retain bends, reversals and colors. Angular wrap handled relative to first non-near-anchor direction. Points within tolerance of anchor impose no angle constraint. Failure commits previous candidate and starts new segment. No chronological eviction; worst memory depends on geometric complexity, cannot promise arbitrary full curve < capped500.

Immutable snapshot storage: linked sealed chunks (<=128vertices) with FloatArray XY + color; bounded copy of mutable current tail per geometry revision. Straight tail updates replace candidate only. Flush chunk on capacity/color/break; color transition starts at previous center (edge uses destination color like old code), invalid/missing pose or observed connection gap starts a new contour. New task/IDLE/explicit stop resets accumulator. Pose marker stays exact, independent of simplification.

Disc config: builder gets local disc center from existing grindingDiscLocalCenter(footprint,length); transform new raw pose to world disc center before simplification. Before settings exist, retain pending raw poses compactly (no fake disc center); when config arrives consume pending once then release. Geometry already recorded keeps calibration used at that time; config changes create new stroke. Need trigger pending consumption from robot-settings observer as well as pose updates. Captured path includes this APP session's actually received poses; no fabricated offline movement. This task doesn't add replay/backfill protocol.

Rendering cache: incremental sealed-chunk projection/native Path, cache by chunk identity; only current tail rebuilt when revision changes; map projection/decoded size/config change rebuilds current geometry, gesture Fit+rotation+zoom+pan via Canvas matrix only. Keep chronology and all color runs, split at invalid/off-map projections to avoid current mapNotNull bridging. Both home overlays share same draw cache; latest robot marker still uses existing toTaskBitmapPoint and dimensions. Native/JVM correctness and benchmark counts/CSV planned; don't silently conflate old500-truncated with full-coverage baseline.
