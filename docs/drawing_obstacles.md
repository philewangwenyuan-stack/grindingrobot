# DXF 图纸地基导入

## 使用流程

新建、编辑地图均在“选择工作区”和“划分工作区”之间增加可跳过的“图纸障碍”步骤。内部依次导入图纸、对齐地图、选择地基、检查确认。沿用 `GlobalTopBar`，急停保持顶部中央红色按钮，Wi-Fi 使用原有右侧青色状态图标。

1. 选择 ASCII DXF，确认单位、图层及解析警告。DWG、二进制 DXF、三维地形不在本次支持范围。
2. 可拖动、旋转粗对齐。添加至少三对分散控制点；图纸侧支持真实顶点、有限直线交点吸附，地图侧通过放大镜、十字线及半像素微调手动取点。
3. 比例默认锁定为 1，同时独立计算实测比例。比例超出 0.995～1.005 或 RMS 超过 20 cm 阻止继续，10～20 cm 提示复核。
4. 点选、框选、同图块批选或手动闭合描边；每个地基可避开或忽略，额外安全间距默认 0.30 m，可设 0～2 m。隐藏图层只影响显示，不取消选择。
5. “检查确认”只校验配准、边界及几何间距，不规划路径。确认后继续划分工作区，最后在原有路径预览中规划；最终保存地图才发布图纸层。

跳过、取消保留已发布图纸层。移除须明确确认，并在最终保存时生效。本地恢复草稿会核对原图 SHA-256、地图几何、坐标系及图纸版本；地图变化后须重新对齐。缓存原图、单位、控制点、选择和手动轮廓保存在 APP 私有目录。

## 存储与规划边界

图纸层以独立 JSON 向量保存于板端 `persist_state_dir/drawing_layers/<map-id-sha256>.json`，包含来源、控制点、变换、地图绑定、版本和地基多边形。默认持久化目录由现有 scheduler 配置决定；关闭持久化时不能跨重启保留。

规划时在请求专用的内存栅格副本中合入地基及额外间距，之后仍使用现有车体安全参数。其作用阶段与 `TaskConfig.obstacle_regions` 的任务障碍相近，但所有权不同：图纸层属于地图且独立持久化，任务障碍属于地图下的一次任务。普通地图禁区继续使用原有 MapService 行为。

图纸不写入 MapService `_overlay`、`overlay.npy`、原始 PGM 或导航运行 PGM；不修改局部 costmap、`/scan` 或 RPP 参数。地基应进入全局路径绕行，但局部避障器不会因此获得新的地基感知能力。全局规划结果检查全部线段和车体轮廓，最终追加的起步连接以及任务启动、恢复前也会复检；不安全则拒绝输出或启动。

地图原始资产版本、尺寸、分辨率、原点、朝向或坐标系变化会使图纸层失效。失效默认阻止任务；仅在用户明确确认后允许绑定当前任务、地图、图纸版本的一次跳过。停止、结束、取消或断线清理授权，不能继承到下一任务。

## 协议与提交

新增 `0x053A/0x053B` 数据通道请求/响应，支持能力查询、分片上传、校验、丢弃。单片 48 KiB、总载荷 8 MiB，SHA-256 校验，响应按 request_id 关联；上传暂存 5 分钟，完整草稿 24 小时。大区域快照沿用区域响应消息编号，以48KiB分片、独立transfer_id和SHA-256回读，完整校验后才向页面发布；最多16MiB、最多两个并发接收，未完成分片15秒过期，断线清空。小响应保持原有格式。所有扩展均为新增字段，`PolygonRegion.process=10` 保留。APP 全量 Java 与板端 Python、lite Java/Kotlin、nanopb SDK 使用 protoc 25.1 同步生成。

确认页生成未发布草稿；最终预览携带 draft_id/version，最终保存携带同一草稿和稳定目标 map_id、request_id。板端先持久化 pending 日志，再调用原地图保存，成功后绑定实际返回地图并发布新版本。重复保存请求返回缓存结果。失败或中断保留 pending 并阻止任务；原请求可重试，重启后仍可利用 pending 重试；地图几何变化时必须重新对齐。不会把地图保存和另一个 JSON 的替换宣称为文件系统级跨文件原子事务。

## 支持范围与限额

支持 LINE、二维 POLYLINE/LWPOLYLINE（含 bulge）、CIRCLE、ARC、ELLIPSE、嵌套 INSERT/阵列及 HATCH 边界（含凸度多段线、直线边、圆弧边）。只读取模型空间；倾斜 OCS、三维多段线、HATCH 椭圆/样条边及其他不支持图元明确报告。HATCH 各闭合边界作为独立实心候选，不自动推断孔洞；用户须核对选择。散线不会自动猜测闭环，可用手动描边。

文件上限 50 MB，展开最多 20 万图元/100 万点，图块嵌套最多 8 层；圆弧按 5 mm 弦误差离散，单弧超过 1 万段则拒绝。发布最多 4096 个多边形/10 万点，每个 3～2048 点，面积至少 0.01 m²。超限要求精简；未对现场大图吞吐量作保证。

MINSERT 阵列间距参与旋转、不参与单个图块缩放，零间距不重复展开；规则核对了 [ezdxf 的参考实现](https://github.com/mozman/ezdxf/blob/master/src/ezdxf/entities/insert.py#L617)。相应回归同时检查单块尺寸与阵列间距。

## 验证与现场验收

离线测试覆盖 DXF、单位、图块、坐标往返、配准、吸附、协议、分片、版本冲突、失效授权、独立存储、提交重试、真实规划器绕障和不安全后备路径拒绝。APP 构建使用 `:app:assembleDevDebug`；板端新测试位于 scheduler `test/test_drawing_*.py`，分文件运行以避免旧 ROS mock 相互污染。

现场验收仍须完成：

- 在实际平板核对急停与 Wi-Fi 位置/颜色、触控缩放、角点吸附、放大微调和原有各步骤。
- 用实际二维基础 DXF 核对单位、图层、块嵌套、每个地基及未支持图元提示；选择分散控制点，使用未参与配准的位置独立复核。
- 新建、编辑、跳过、取消、移除、断线、保存超时和重启恢复各验证一次；核对地图编号和图纸版本。
- 对比原始及导航 PGM、overlay 的哈希和普通禁区行为；图纸发布前后仅独立图纸 JSON 和全局规划结果应变化。
- 在隔离场地验证起步、连接段、转弯车体包络、窄通道、不通行提示、暂停恢复、停止和急停；观察真实车体偏差与现场安全间距。
- 替换原图使图纸失效，验证默认阻止、仅本次跳过、下一任务再次确认；无图纸地图和普通任务应保持原有行为。

## 实际图纸解析与预览修复（2026-11-03）

以用户提供的“花都构件厂地基基础精简版.dxf”复现。该图含大量嵌套图块及 HATCH，旧实现跳过边型和凸度边界；现支持其全部889条HATCH边界，并验证顺/逆时针圆弧、边连续性与闭合性，不用虚构线段补齐断裂轮廓。文字/属性/尺寸标注继续排除，作为灰色说明显示；5个ACAD_PROXY_ENTITY仍保留未支持提示，不能保证其内部内容已提取。

导入预览原先复用雷达地图的投影尺寸及剔除范围，大图只会显示地图附近局部。现导入阶段按CAD全图边界独立缩放和居中，进入对齐后仍使用原地图坐标及配准变换；视口剔除改为按实际可见范围判断。步骤或图纸变化重置视口，急停、Wi-Fi、任务及板端行为未改。

离线解析得到15237个图元、889条HATCH边界，与ezdxf1.4.5独立解析结果逐边双向对照，最大偏差3.441259mm（小于5mm离散精度）。几何预览图来自解析数据绘制，不是APP截图。新增单元回归覆盖直线HATCH、逆时针/顺时针圆弧语义中的顺时针样例、凸度边界、断裂拒绝及全图适配。可选真实文件回归通过环境变量DXF_REAL_FILE指定上述花都图纸，原始私有图纸不提交到Git；DXF_GEOMETRY_DUMP可导出几何用于独立比较。


## 对齐交互微调（2026-11-03）

图纸旋转默认每次0.005°，可切换0.1°和1°，当前角度显示三位小数。已有待确认图纸点时围绕该点旋转，否则围绕图纸中心旋转，避免大CAD坐标下围绕原点旋转产生平移。已有控制点时仍需先清空才能粗调；正式配准继续由至少三对控制点求解。

控制点少于三对时，底部主按钮显示“添加控制点”，点击后提示选图纸点、选地图同一点、确认这一对的具体阶段，不再静默无响应。右侧增加待确认控制点按钮；未完成求解时显示“RMS —”，不再把初始0值显示为绿色合格。配准结果的残差数必须与当前控制点数匹配且有限，之后仍执行原来的RMS及比例门限；未验证的手动对齐不能发布。
