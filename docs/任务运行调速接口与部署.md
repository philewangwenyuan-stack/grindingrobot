# 任务运行调速

导航任务运行或暂停时，点击状态卡的“直行速度”或“研磨转速”，先读取板端当前设定和范围，再输入数值并应用。设定值和实测值分开显示；仅在收到匹配任务与请求的成功回复后更新设定值。应用失败、断线或超时会提示原因，可重新打开读取当前值。

修改只对本次任务生效，不写默认设置、YAML 或持久化文件。暂停时允许修改，恢复后使用新值；暂停、结束和急停入口继续使用原安全链路。转速更新不发送磨盘使能，连接路径的转速继续由原逻辑控制。任务停止、完成或异常后清理临时值；下一任务开始前必须成功恢复原直行速度。

## 协议

- 请求 `0x0538`，回复 `0x0539`，组件 `COMP_SCHEDULER=0x08`，沿用 SL-LinkA 帧和 CRC。
- `TaskRuntimeSettingsRequest`：`task_id`，可选 `run_speed`（m/s），可选 `disc_speed_rpm`。两项都缺省时只查询；显式传 RPM=0 是合法修改。
- 回复包含 `result/message/task_id`、当前设定、速度和 RPM 上限、`temporary=true`。回复 `ack_seq` 必须匹配请求 `seq`，任务 ID 和来源也必须匹配。
- 速度必须大于 0，最大为底盘与 RPP `max_linear_vel` 上限中的较小值。只动态修改 RPP `desired_linear_vel`，不调整加速度或避障参数。零速度需使用暂停。
- 转速范围为 `0..task_runtime_max_disc_speed_rpm`，新增 YAML 参数默认 1500 rpm。该值是软件上限，部署前应与机器允许范围核对。
- 当前实现要求 RPP 控制器。旧板端没有新协议，APP 会超时提示更新板端，不会改发永久设置请求。
