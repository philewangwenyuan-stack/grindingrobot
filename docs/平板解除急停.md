# 平板解除急停

首页顶部只保留同一个按钮：未急停时显示红色“紧急制动”，已急停时显示橙色“解除急停”。解除时先确认现场安全、实体急停已释放，再请求板端执行解除检查。实体急停与底盘反馈的校验全部由板端执行，APP 不绕过校验。

`DeviceStatusReport` 新增 `optional bool emergency_stop_latched=22`，读取板端运动锁存的实际状态；支持重连、其他客户端触发急停和实体急停经底盘/调度上报后的同步。未知或旧板端缺少字段时不猜测已解除，仅保留制动入口；本次连接中确认的急停/解除回复可切换按钮，断线后清为未知。

沿用 `ControlCommand.emergency_stop.enabled=false`，原 `0x0401/0x0402` 控制指令及回复不变，目标设备和组件沿用现有急停通道。false 仍带 emergency_stop 子消息，不是空控制请求。控制请求不变，状态协议新增上述可选字段。

请求等待最长 10 秒，独立 tracker 严格匹配 ACK 序号和来源；不会使用旧协议 ack=0 的模糊匹配。重复点击不重发。等待解除期间，同一个按钮显示“紧急制动”，并提示“正在解除，点击可再次急停”；新急停取消 APP 的解除等待和过时结果。取消等待不会撤回已写入 socket 的请求，板端仍必须使用现有急停代次校验处理并发。

成功、拒绝、发送失败和超时均显示结果，板端返回的原因完整保留。超时表示结果未知，不自动重试、不自动启动。无底盘测试模式若仅清灯而仍锁存，按板端失败回复显示拒绝。

解除成功后按钮切回“紧急制动”，设备保持停止，必须重新点击启动。拒绝、超时不会自行切为正常状态，继续依据板端上报或本次已确认状态显示。APP 不发送任务启动、使能或速度命令。

自动跟随实际急停状态依赖板端同步更新新状态字段及生成的 Python 协议。本次修改本地板端状态上报和各 SDK；未远程部署或执行真实解除。

## 验证

TCP 模块 78 项测试通过，包含解除指令编码、回复严格关联和急停状态未知/false/true 的兼容性。main 共 9 项定向测试通过，覆盖五种单按钮状态，以及重复点击、等待确认、新急停打断迟到解除、拒绝与超时反馈。板端 Python 语法和生成协议三种状态往返校验通过。

main 常规单测编译存在已有 GNSS 测试引用缺失类型的问题（com.example、MainViewModel、GNSSData 等），本次未修改这些测试。使用临时 Gradle init 文件仅选择新增测试源码，并跳过该纯 Kotlin 测试不需要的单测 KSP；复制测试源码与原文件哈希相同。因 Windows 原 classes.jar 被其他进程占用，main/app 输出切到 `app/build/emergency-release-isolated`，生产源码和 APK 构建配置不变，`:app:assembleDevDebug` 成功。

单按钮版本输出 `app/build/outputs/apk/dev/debug/grindingrobot-emergency-state-{arm64,arm32}-debug.apk`，板端更新包 `app/build/outputs/board/grinder-emergency-state-update.zip` 按相对目录更新 scheduler 和 Python 协议，包含生成 SDK 与基准哈希清单。更新前备份并确认任务已停止，通过原有流程重启服务后上报新状态。未进行真实底盘解除、实体急停或真机 UI 验证。
