# 擦除区域编辑与性能优化

本次只修改 Android 建图 Step2/3，不修改障碍区编辑、板端协议或运行程序。

## 操作

- 矩形擦除：空白处单指拖出矩形，也可点击创建默认框。框内拖动移动，右下蓝点调整大小，✓ 确认，✕ 取消。已有选区时，点框外保留选区。
- 涂抹擦除：单指画一笔，松手确认，滑条调整屏幕笔宽。撤销/重做按整笔处理。
- 上述两种工具都支持双指缩放、平移，无须切换到移动工具。双指操作后，即使只剩一个手指，也等全部抬起后才允许下一次编辑。
- 缩放继续使用全局 1–8 倍模型和共享中心位置。没有新增旋转手势。
- 当前未确认矩形必须先确认或取消，再进入下一步。

## 性能变化

1. Step2/3 复用同一冻结底图的解码结果，最多缓存一张；首次解码在 Default 后台线程完成。缓存锁不包围解码过程，避免 UI 查询缓存时等待解码锁。
2. Step2 的已确认擦除合并为位图坐标 Path，回显区域按区域列表、地图投影参数缓存 Path。Step3 缓存擦除回显 Path。所有擦除回显合成一个白色填充 Path，1,000 个区域由 1,000 次填充绘制降为 1 次；统一轮廓绕序，避免反向多边形重叠处出现空洞。缩放/平移/显示旋转只调整 Canvas 矩阵。
3. 擦除提交前的世界坐标编译移到 Default 后台线程。编辑每一笔、撤销、调角时不再重建整个提交结果；每个 ACK 也不再重复投影全部剩余区域。
4. Step3 在服务器查询返回之前，先使用本冻结会话内已获 ACK 的擦除区域；服务器返回后以最新结果替换。跨会话不沿用旧区域。
5. 涂抹按笔宽的 1/12 误差简化折线，编译为两端为圆弧的凸多边形。地图边缘执行多边形裁剪，三角形也可正常提交。直线涂抹只需一个多边形；折返和弯角保留。松手后的显示几何与提交几何共用同一份多边形。

下一步仍然串行等待每个擦除多边形的设备确认，然后进入 Step3。现有 MapEditResponse 没有 edit_id，不能直接并发请求并正确匹配响应。本次没有通过跳过 ACK 来缩短等待。界面显示已提交/总数；重试复用稳定区域 ID，已确认的部分不再次发送。复杂长笔画可能拆成多个多边形，仍有多次设备往返。

## 验证

- 6 项涂抹几何测试：边缘裁剪、单点圆笔迹、长直线压缩、折返、逐点误差上限、矩形反向拖动。
- 5 项提交几何测试：位图与逻辑地图不同尺寸、角度撤销、世界朝向、三角形、多段编号、未确认区域不提交。
- 原有 9 项擦除交互几何测试，以及 2 项全局 viewport 测试；共 22 项单元测试通过。
- Android 12 模拟器 6 项原生测试：矩形移动后框外点击不回缩、双指缩放及剩余单指不误移框、涂抹与缩放隔离、空白拖矩形、区域缓存失效条件、相反绕序多边形的重叠填充。
- 缓存计数测试：1,000 个矩形首次投影 4,000 点，随后 120 次相同几何复用新增投影为 0；投影参数或区域列表变化时重新构建。该数据是计算次数，不是现场帧率。
- 10,001 点直线涂抹在容差内压缩为 2 个端点，生成 1 个协议多边形；不按固定点数截断。
- `:app:assembleDevDebug` 与 `:feature:map:assembleDevDebugAndroidTest` 成功。

原生测试运行在临时隔离模拟器，仅安装 library test APK，无机器人连接或实机部署。实际设备上的等待时间与触摸手感尚未现场确认。测试结果位于 `artifacts/erase-editor/`。
