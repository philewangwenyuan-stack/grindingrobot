# 机器人图标等比例缩放与手势缩放联动重构设计文档

为了提升机器人视觉呈现的物理精确度，SinelMC 项目对 APP 地图中的机器人图标 `ic_robot` 进行了等比例尺寸重构。此重构使机器人图标大小能根据车身实际长宽比例进行呈现，并在地图手势缩放（双指放大/缩小）时联动缩放，同时融入了 `16.dp ~ 100.dp` 的安全可视限值保护。

本重构坚持“**非破坏性开发**”原则，若车辆物理参数未读取成功或未配置，将自动降级至原版默认尺寸，绝对不影响原本的基础功能及稳定性。

### 2. 双向通讯与实时更新闭环
原本的“参数写入”操作（`MSG_ID: 0x0206`）仅在界面弹出了成功 Toast 却遗漏了同步本地缓存。现已实现完美闭环：
*   **[SlLinkManager.kt](file:///c:/Work/Code/grindingrobot/core/tcp/src/main/java/com/sinelynx/grindingrobot/core/tcp/SlLinkManager.kt)**：在处理参数写入成功的响应中，如果下位机回显了新的地图/车体设置，立即调用 `appState.updateRobotSettings` 和 `appState.updateMapSetting` 同步全局状态。
*   **[RobotSettingsViewModel.kt](file:///c:/Work/Code/grindingrobot/feature/main/src/main/java/com/sinelynx/grindingrobot/feature/main/viewmodel/RobotSettingsViewModel.kt)**：在参数写入请求获得成功回调时，主动将最新的内存长宽数据写入本地的全局 `AppState` 缓存，用作双重兜底。实现“在设置页面一修改，全局地图立刻以新比例重绘”的联动效果。

### 3. 可视比例计算算法设计
为了在“物理等比准确性”和“人眼可视清晰度”之间达成完美的系统平衡，我们采用以**各界面的标准可视尺寸为缩放基数**，结合物理宽高比和手势缩放系数进行乘积计算的方案。这避免了因为直接根据物理分辨率换算导致折合像素过小（如只有 1.3dp）而卡死在 16.dp 极小值下限的问题。

#### 📐 算法原理：
以默认基准大小 $DefaultSize$（如 `40.dp` 或 `42.dp`）作为缩放核心：
1. **宽高比例计算**：
   - 如果 $Length \ge Width$，则基准长度为 $DefaultSize$，基准宽度为 $DefaultSize \times \frac{Width}{Length}$。
   - 如果 $Length < Width$，则基准宽度为 $DefaultSize$，基准长度为 $DefaultSize \times \frac{Length}{Width}$。
2. **手势联动与限值限制**：
   - 实际渲染宽度 = $(BaseWidth \times Zoom).coerceIn(16.dp, 100.dp)$
   - 实际渲染高度 = $(BaseLength \times Zoom).coerceIn(16.dp, 100.dp)$
   - 保证了在放大/缩小手势过程中，图标不仅比例端正（窄车更窄，长车更长），且随地图平滑变大变小，且最大不超过 `100.dp`，最小不低于 `16.dp`。

## 🎨 UI 与页面层重构细节

### 1. [MapRobotMarker.kt](file:///c:/Work/Code/grindingrobot/feature/map/src/main/java/com/sinelynx/grindingrobot/feature/map/ui/MapRobotMarker.kt)
*   `FittedMapRobotMarker` 引入 `robotWidth` / `robotLength` 参数。
*   重载 `RobotPoseIcon` 方法：
    - 新版重载支持独立的 `width: Dp` 和 `length: Dp` 渲染，以呈现不等比例轮廓。
    - 旧版重载继续接收单一 `markerSize: Dp` 并完美向下兼容。

### 2. [DeviceStatusScreen.kt](file:///c:/Work/Code/grindingrobot/feature/device/src/main/java/com/sinelynx/grindingrobot/feature/device/ui/DeviceStatusScreen.kt)
*   **`CenterRobotMarker`**：将基准宽/高（`36.dp` 和 `48.dp`）结合实际比例及手势 `zoom` 进行动态重算。
*   **`ZoomableTaskTrajectoryOverlay`**：在轨迹图层上以基准 `42.dp` 结合宽高比及 `zoom` 动态控制 Canvas 渲染中机器人图标的布局大小及居中偏置。
*   **`TaskTrajectoryOverlay`**：普通轨迹层同步以物理长宽比例作为初始展示尺寸。

### 3. [MapScreenStep2.kt](file:///c:/Work/Code/grindingrobot/feature/map/src/main/java/com/sinelynx/grindingrobot/feature/map/ui/MapScreenStep2.kt) 与 [MapScreenStep3.kt](file:///c:/Work/Code/grindingrobot/feature/map/src/main/java/com/sinelynx/grindingrobot/feature/map/ui/MapScreenStep3.kt)
*   在这两个步骤的手势地图编辑视口中，利用 `zoom` / `mapZoom` 对调用的 `RobotPoseIcon` 的大小进行同步缩放，解决了以前缩放时机器人相对底图显得“反向变大/变小”的问题。
*   由于属性委托的线程安全机制，在 `MapScreenStep3.kt` 中我们通过提前解构为局部不可变变量的方案完美避开了 Kotlin 的智能非空转换限制（Delegated Property Smart Cast Issue）。
