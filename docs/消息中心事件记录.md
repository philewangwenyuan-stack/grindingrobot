# 消息中心事件记录

点击顶部铃铛查看。每条显示事件内容及 `yyyy-MM-dd HH:mm:ss` 时间，新消息在前，可滚动查看。时间是 APP 检测到连接变化或收到板端状态时的本机时间，不受弹窗打开时间影响。

弹窗默认完整显示三条消息，标题旁显示总条数。超过一屏时，右侧显示滚动轨道与滑块，可拖动滑块或点击轨道快速定位；滑块大小与位置反映当前查看范围。

点击消息中心弹窗内部右下角“清空消息”可删除已记录的事件和本地保存的历史，重新打开 APP 也不会恢复；之后的新事件继续记录。按钮在暂无消息时也显示。当前低电量提示属于实时状态，仍会按当前电量显示。

记录以下状态变化：

- APP 与工控机首次连接、断开、重新连接。连接尚未成功时的重复失败不记录为断开。
- RPP `collision_imminent` 从未激活变为激活，记录“RPP 检测到障碍物，已触发避障停车”；解除时记录解除消息，不表示任务一定已恢复运行。
- 工控机与底盘断开、恢复。底盘状态来自驱动 `/chassis/status.connected`；已收到样本后超过 3 秒没有新状态也报告断开。该检测只用于诊断消息，不改变运动控制逻辑。

事件在通信回调中采集，不依赖页面或消息弹窗打开；APP 运行期间已记录的消息通过 MMKV 本地保留，关闭再打开仍可查看。最多保留最近 500 条。APP 没有运行或与工控机断开期间发生的板端事件无法补记；重连后只能记录当时收到的状态。

## 协议兼容与板端更新

`DeviceStatusReport` 新增 `optional bool chassis_connected = 21`。显式 false 表示断开；字段缺省表示旧固件或尚无底盘样本，APP 不按 false 处理。保持原消息 ID、帧格式和 CRC。

本地板端源码位于 `E:/CODE/C++/Grinder`，更新需同步 scheduler_node.py、proto 及 Python 生成协议。Android、Python、nanopb SDK 均按 protoc 25.1 重新生成。没有部署到工控机、重启服务或操作硬件。

旧板端仍能记录 APP/工控机连接和已有的 RPP 状态。底盘断连消息需要安装本次更新的板端代码并通过现有流程重启服务后才可用。板端更新应在任务结束、设备停稳后进行。
