# 系统状态

设置左侧“系统状态”为与软件设置、硬件设置并列的可点击一级入口。

页面显示机器人板端的左右伺服电机故障码、底盘连接/使能、磨盘使能、急停、CPU温度/占用率、内存占用/可用与总量、地图所在磁盘占用/剩余空间、本次开机时长，以及导航雷达原始状态、定位就绪和碰撞保护。碰撞状态不能推断避障雷达健康，后者尚未独立上报。

电机故障码0显示正常，非0保留int16十进制及16位十六进制原值，未接入故障码含义表。只有板端底盘反馈新鲜且连接时才上报电机码。APP断线、未收到或超过3秒未收到状态时清空可见读数，显示未知。缺失可选字段不会当作0或正常。

协议保持原DeviceStatusReport消息ID、组件ID、帧及CRC规则，增加26/27左右电机可选int32字段（范围int16），28为SystemHealth消息，其CPU温度、CPU/内存/磁盘百分比、内存/磁盘字节数、开机秒数均有字段存在性。旧APP忽略新增字段，旧板端在新APP中显示资源数据未提供。

板端`system_health.py`独立线程每2秒读取/proc/stat差分、/proc/meminfo的MemAvailable、CPU/SoC热区和磁盘空间；第一个CPU样本不显示占用率，失败项不保留旧值，采样整体超过5秒过期。通信线程只复制内存快照。APP每2秒刷新可见页面，无新增轮询请求。

系统状态内容采用2×2卡片，无纵向滚动；顶部沿用GlobalTopBar（急停居中，通知/Wi-Fi等在右侧），明确置于页面内容之上。通信卡片分别显示平板Wi-Fi名称/RSSI以及板端数据、控制通道RTT。RTT利用已有会话心跳，从实际socket写入到匹配ACK接收计时，包含链路和板端响应时间；断线/换连接/超过3秒未确认则不显示旧值，不以状态消息更新时间代替延迟。

4G为机器人板端数据，增加SystemHealth可选信号百分比及连接状态、实际接入制式。通过ModemManager只读查询，只有单个已注册/连接的调制解调器且信号为recent时才填百分比，未安装工具、超时、多个不明确设备、缓存过期或外部4G路由器未提供接口时显示未提供。查询不打开无线、不拨号、不发AT命令，每条只读命令400ms超时。字段依据[ModemManager官方信号质量定义](https://www.freedesktop.org/software/ModemManager/doc/latest/ModemManager/gdbus-org.freedesktop.ModemManager1.Modem.html)。本轮板端网络不可达，未确认现场4G硬件能否由该接口读取。

需要同时更新板端scheduler_node.py、system_health.py和Python协议生成文件sl_link_pb2.py，以及APP APK。仅更新APP不能获得新增资源与电机字段。此次只修改本地源码，未部署/重启板端。

验证：板端纯Python单测；APP SystemStatusDecoderTest覆盖旧版缺字段、有效0、负故障码/64位内存值、非法浮点与断线清空；全APP DevDebug构建。实际板端只读运行采样代码验证可读资源，不替代板端部署后的端到端验收。
