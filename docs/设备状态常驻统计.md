# 设备状态常驻统计

状态和任务统计使用固定侧栏高度内的两个卡片，空闲、待开始、运行和暂停时都显示。
空闲时任务总面积、已磨面积、剩余面积及剩余时间显示“—”；今日和累计项继续显示。

## 数据来源

- 当前任务：TaskStatusReport 实时上报，已磨面积为总面积减剩余面积。
- 今日总研磨面积：全部地图执行历史的 executed_area_m2，按设备/Android 本地日期归属执行开始日。
- 机器总研磨面积：设备返回的全部保留执行历史的 executed_area_m2 之和。
- 今日工作时间、机器累计作业时间：板端独立 `work_time_statistics.json` 计数，通过历史响应JSON的 `work_time_statistics` 对象读取。删除任何/全部历史均不改变这两个时间；APP不根据历史重新求和，也不自行延长“运行中”历史的时长。
- 首次升级只迁入仍保留且起止时间有效的历史时长；旧的RUNNING/finished_at=0不补造结束时间，永久保留不完整标记，界面以已确认下界（如“≥52分”）和“计时不完整”提示。删除缺失记录不会抹去标记或再触发迁移。
- 未更新板端时，时间显示“—”并提示“需更新板端”；计数对象无效或存储失败显示“计时读取异常”，不以历史合计/0冒充独立计数。
- 同 execution_id 去重，实际面积的负数及非有限值不计入。

页面可见时进入查询，每30秒刷新，任务身份或运行状态变化时额外查询。离开页面停止后台查询。
查询与历史记录、作业统计页面共享请求锁，不同时占用历史分片组装器。
成功的空历史仅使面积为0，时间仍显示独立计数；读取失败保留上次结果并提示“统计更新失败”。

## 现有协议边界

独立计数沿用任务经过时长口径，包含暂停，不计空闲/手动遥控/服务停机，并非纯研磨电机开启时间。
累计面积来自保留历史，删除历史会影响累计值，不等同于设备不可清零的终身计数器。
跨午夜的执行面积按开始日归属；没有按日分段面积，无法精确拆分午夜前后的研磨面积。
正在执行的今日面积依赖设备历史接口是否包含活动执行记录；若仅返回结束记录，则任务结束后刷新计入。
今日时间由板端按本地午夜切分，APP不使用平板时间外推计数。此前已经删除的记录无法恢复，升级后的累计以能迁入的已确认值为基础继续增加。计数每5秒及任务开始/结束时由后台线程持久化；正常关闭等待保存，突然掉电只恢复最后成功检查点，缺失尾段标记不完整，不计停机时间。
累计文件与历史文件应一并备份；损坏时明确报错，不静默清零或依据剩余历史重建。若设备全部已确认累计工作都在今天，两项时间仍可以正常相等。

## 验证

已补充历史删除不影响时间、旧板端/无效计数、独立基线/缺失标记、面积去重、时间格式，以及停止任务保留统计的测试。
2026-10-26只读核对现场板端：全部保留历史共9条，开始日期均为2026-10-24；当前实时任务状态为IDLE，但两条历史仍为RUNNING且finished_at=0。7条已结算记录共3175秒（52分55秒），缺失的两条不能恢复为精确总时长。本轮补充真实时间戳回归、空闲时不续计、不同任务、重复执行、跨午夜有效暂停，以及同日正常相等等用例。现场数据未改写，未重启或部署板端。

独立计数版本：TCP98项、设备模块55项（其中统计12项）通过，`:app:assembleDevDebug`成功；板端独立计数16项在Windows及WSL Linux通过，相关启动/续跑/临时参数/急停44项通过。新APK需配套更新板端计数模块及调度接入代码。没有远程部署、清历史、启动任务或重启设备。
